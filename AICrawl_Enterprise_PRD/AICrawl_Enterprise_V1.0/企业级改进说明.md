# 第一轮工程化改进

本轮在原有前后端闭环上补齐运行可靠性与可维护性，继续遵循“不接数据库”的当前要求。全部实现与运行产物均位于 `AICrawl_Enterprise_V1.0`。

## 已落地

| 问题 | 改进 | 验证 |
|---|---|---|
| 每次启动创建线程，没有并发上限 | 固定采集线程池，默认 4 个 Worker，运行中/排队/暂停批次合计最多 32 个；满载返回 429 | 队列容量、关闭测试 |
| 提交超时后重复执行 | 启动 Run 支持 `Idempotency-Key`，同任务同键返回原批次，完成后仍保留 | 20 次并发相同键只创建 1 个批次 |
| 暂停与发布并发边界 | 阶段不跳过，提交时重新校验来源和取消状态；关闭时取消未完成批次 | 暂停恢复、取消不发布、停源不发布 |
| HTTP 连接线程无界 | 16 个 HTTP Worker，最多 32 个受理连接；超出连接关闭，读取超时默认 10 秒 | HTTP 集成回归 |
| 配置写死 | 独立不可变 Settings，环境变量启动校验 | 参数范围验证 |
| 错误难定位 | 响应头及错误体含请求 ID；审计、批次、日志关联同一 ID；未处理异常转为脱敏 500 | 非法 JSON、错误 ID 类型、请求 ID 测试 |
| 内存无限增长 | 来源、任务和历史批次分别有数量上限，审计滚动保留，记录数量受限 | 容量检查 |
| 日志散落 | `logs/application.jsonl` JSON 日志，单文件 2MB，3 个备份 | 实际启动验证 |
| 查询只能获取全量 | 新增分页资源接口、状态过滤、关键词查询，每页最多 100 条 | 分页、筛选测试 |
| 前端请求可能堆积 | 串行轮询，隐藏页面暂停轮询，10 秒请求超时，错误提示请求 ID | JavaScript 语法检查 |
| 运维不可见 | health / ready / metrics，前端展示工作线程和活跃批次容量 | 健康探针验证 |

## 配置与运行

不读取 `.env` 文件，不需要额外安装依赖。PowerShell 示例：

```powershell
cd AICrawl_Enterprise_V1.0
$env:AICRAWL_PORT = '8000'
$env:AICRAWL_WORKERS = '4'
$env:AICRAWL_MAX_PENDING = '32'
$env:AICRAWL_MAX_HISTORY = '1000'
$env:AICRAWL_REQUEST_TIMEOUT = '10'
python run.py
```

`--port` 优先于 `AICRAWL_PORT`。仍只监听本机 `127.0.0.1`。Ctrl+C 停止时取消未完成批次并关闭执行池，不会将取消批次发布为成功。进程崩溃和强制结束后，内存内容仍会丢失。

新增接口：

```text
GET /api/v1/ready
GET /api/v1/metrics
GET /api/v1/sources?page=1&page_size=20&status=ACTIVE&q=招聘
GET /api/v1/jobs?page=1&page_size=20
GET /api/v1/runs?page=1&page_size=20&status=SUCCEEDED
GET /api/v1/records?page=1&page_size=20&status=PUBLISHED
GET /api/v1/audit?page=1&page_size=20
```

分页返回 `items/total/page/page_size`。`/state` 为兼容当前控制台保留全量快照；后续前端迁移分页 API 后移除此兼容入口。

Run 创建可设置 `Idempotency-Key: <1–128字符的键>`。调用方需要在重试时复用相同的键；不同操作需要新键。原生前端每次主动提交生成新键，暂不自动重试修改操作，超时时提示用户检查批次状态。幂等信息仅在当前进程有效。

## 后续企业部署工作

本轮是企业化工程基础，尚未达到生产部署验收。当前依然为本机单用户、内存数据、本地样本；没有真实租户隔离、身份认证、RBAC、数据库事务、持久化审计、执行租约、进程重启恢复或真实网络抓取。

下一阶段建议按依赖顺序推进：身份认证与权限模型 → Repository 与数据库事务 → Outbox 和独立 Worker → 获准来源的 HTTP 采集适配器及网络策略 → React 管理界面与分页 API → 部署、安全与压测验收。引入数据库前继续保持当前内存版本可独立运行。
